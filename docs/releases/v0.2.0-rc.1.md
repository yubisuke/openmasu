# OpenMasu v0.2.0-rc.1

`v0.2.0-rc.1` is an early release candidate built from source and synthetic
automated evidence. It is not a production-readiness claim. The product release
number is independent of the active Contract v0.4 identity.

## Added since v0.1.0

- Replayable deterministic fraud controls with source-day rules, bounded click
  evidence, registered rule-bundle binding, quarantine resolution, gross/net
  metrics, and aggregate audit output.
- Direct Android App Links and iOS Universal Links, Android deferred deep links
  through Install Referrer, Unity callbacks, engagement-scope attribution, and
  separate daily reporting.
- Verified conversion delivery foundations for Play-verified purchases,
  source-qualified Google Ads clicks, encrypted durable requests, Data Manager
  diagnostics, and deletion-before-dispatch purging.
- Reproducible local SDK artifacts: Maven AAR/POM files, a Unity UPM archive, a
  Swift source archive, CycloneDX SBOMs, and SHA-256 manifests.
- Verified commerce lifecycle processing for authenticated Google Play signals,
  exact Orders refunds, App Store Notifications V2 JWS verification, encrypted
  read-back cursors, privacy purge, and retry/idempotency handling.
- Admin lifecycle operations, installation-scoped SDK-authenticated access and
  portability, digest-only deep-link audits, and canonical attribution, metric,
  and Apple-postback provenance.
- Append-only MAX aggregate-revenue snapshots with restatement history and a
  current-view projection.

## Contract status

- The active wire identity remains Contract v0.4.0; existing v0.4 schema IDs and
  artifact `contract_version` values do not change in this release.
- Additive v0.4.1 through v0.4.9 work adds fraud, deep-link, commerce, and
  long-horizon metric evidence while maintaining independent TypeScript/Python
  evaluator and RFC 8785 parity.
- The v0.4.6 fraud-provenance correction changed seven reviewed fraud-decision
  goldens. It is a semantic correction rather than a wire-format break.

## Compatibility and operations

Product/API additions and database migrations are forward-compatible additions.
Operators must migrate forward. The release runbook does not support destructive
schema rollback or resurrection of redacted payloads.

## Residual boundaries

- No production deployment, live provider authorization, real credentials,
  provider acceptance, quota behavior, notification delivery, or diagnostics
  latency has been demonstrated.
- No real device, campaign, store-track, Unity export, App Store review,
  consumer-project, reinstall, or four-week re-engagement validation has been
  completed.
- Registry publication, artifact signing, production TLS and secret management,
  real backups, representative capacity, alert ownership, incident response,
  and formal trademark clearance remain operator responsibilities.
- Fraud calibration, live integrity projects, false-positive rates, real device
  farms, reset fraud, and cross-advertiser intelligence remain outside the
  synthetic evidence.
- iOS deferred deep linking is not offered. Direct `deep_link_open` events are
  device-reported and forgeable evidence.
- An SDK installation credential proves control of that installation only.
  Custom non-fraud rule semantics require separately reviewed contract work.
- Verified commerce does not establish entitlement, tax, payout, complete missed
  renewal reconstruction, or Apple installation-level revenue binding.

The complete milestone and adapter boundaries are recorded in
