# Unreleased Source

This is a living summary of source changes after the published prerelease,
not release notes for a new version. It does not select a release number,
promise a date or claim new SDK assets are published.

## Published baseline

`v0.3.0-rc.1` is the current published source and SDK prerelease at `90a0f5f`.
Its [release notes](v0.3.0-rc.1.md),
[synthetic evidence](../validation/v0.3.0-rc.1-synthetic-evidence.md) and
[publication receipt](../validation/v0.3.0-rc.1-publication.md) remain fixed to
that tag. Later source changes must not be added to those historical receipts.

## Current source additions

Current source extends the contract patch ledger through `v0.4.24`; the wire
identity remains `0.4.0` with `:v0.4` schema URNs. The current inventory and
limits belong to [Project status](../STATUS.md), not another duplicated count.

The unreleased source connects:

- selected first-party, verified platform and imported acquisition profiles;
- safe cost grain, purchase/refund/reversal, detailed acquisition and separate
  first-party re-engagement outcomes;
- saved calculation/comparison meaning, explicit calendar/FX definitions,
  same-set acquisition KPIs and mature D3/D14/D30 retention;
- multiple custom outcomes, guided schedule setup and receipt/freshness diagnostics;
- bounded cost/late-input/privacy corrections, confirmed ingest recovery and
  durable schedule recovery;
- existing controller, pure evaluator, SQL and ingestion boundaries with
  simpler, non-overlapping CI test ownership.

The [documentation index](../README.md) links the corresponding guides.
These are source implementations with synthetic evidence; they do not qualify
live providers, devices or production operation.

## Remaining integration work

The [current functional plan](https://github.com/yubisuke/openmasu/issues/218)
and [roadmap](../roadmap.md#next-product-sequence) prioritize minimal monitoring
and scheduled backup, followed by saved daily analysis, broader comparison,
Apple aggregate usability and Unity purchase binding. Optional extensions have
separate usage conditions; they need not all precede candidate promotion.

An integrated candidate must bind its source, contract, SDK identities,
documentation, upgrade procedure and artifacts to one accepted commit. Follow
the [release runbook](../operations/release.md); do not relabel an untagged
bundle or older release evidence as a newly published candidate.

## Unverified boundaries

Real provider permissions/connections, device delivery, store approval, domain
association, production capacity, alert delivery and recovery objectives remain
separate private operator evidence. Synthetic completion does not establish
commercial-provider equivalence or production readiness.
