# OpenMasu v0.2.0-rc.4

`v0.2.0-rc.4` is an early release candidate built from public source and
synthetic automated evidence. It is not a production-readiness claim and does
not claim equivalence with, or replacement of, an existing MMP. The product
release number remains independent of the active Contract v0.4 identity.

## Changes since v0.2.0-rc.3

- Added additive Contract v0.4.10 support for AdAttributionKit re-engagement
  postbacks, explicit install and re-engagement conversion targeting, and
  optional opaque conversion tags. The signed receiver, TypeScript and Python
  evaluators, PostgreSQL parity, metric grouping, and reviewed fixture remain
  aligned.
- Added host-application configuration guidance for developer-copy endpoints,
  the re-engagement-copy opt-in, and overlapping-conversion opt-in. Overlapping
  conversions remain disabled by default because tag lifecycle is owned by the
  host application.
- Reorganized current documentation around standalone source-of-truth pages,
  separated current source from historical review material, and made prepared
  candidate identities distinct from published GitHub tags.
- Aligned runtime configuration documentation with bootstrap and Compose,
  including public tracking-link generation while the disposable synthetic
  pilot continues to probe the redirector through its isolated internal route.

The Contract wire and package identity remains `0.4.0`. The additive patch
ledger advances from v0.4.9 to v0.4.10, and the reviewed inventory advances from
56 fixtures and 728 golden artifacts to 57 fixtures and 741 golden artifacts.

## Contract status

- The active wire identity remains Contract v0.4.0; existing v0.4 schema IDs,
  package versions, and artifact `contract_version` values do not change.
- Contract v0.4.10 is additive. It extends existing Apple postback and metric
  surfaces without removing or renaming a v0.4 field.
- Deterministic TypeScript/Python evaluation, PostgreSQL parity, RFC 8785
  canonicalization, and reviewed synthetic golden checks remain required.

## Residual boundaries

- No production deployment, live provider authorization, real credential,
  provider acceptance, quota behavior, notification delivery, or diagnostics
  latency has been demonstrated.
- No real data, device, campaign, store track, Unity export, App Store review,
  reinstall, developer-copy delivery, or consumer-project validation was used.
- Registry publication, artifact signing, production TLS and secret
  management, real backups, representative capacity, alert ownership,
  incident response, and formal trademark clearance remain operator work.
- Fraud calibration, live integrity projects, false-positive rates, real device
  farms, reset fraud, and cross-advertiser intelligence remain outside the
  synthetic evidence.
- iOS deferred deep linking is not offered. Direct `deep_link_open` events are
  device-reported and forgeable evidence.
- An SDK installation credential proves control of that installation only.
  Verified commerce does not establish entitlement, tax, payout, complete
  missed-renewal reconstruction, or Apple installation-level revenue binding.
- AdAttributionKit re-engagement parsing and update targeting are synthetic
  contract and SDK capabilities. Real postback delivery, conversion-window
  behavior, and host-owned conversion-tag persistence remain unverified.

The boundaries above are authoritative for this candidate. The candidate is a
published prerelease only if the annotated tag and GitHub release point to the
same green `main` commit.
