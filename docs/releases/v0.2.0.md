# OpenMasu v0.2.0

`v0.2.0` is the first non-prerelease, pre-1.0 OpenMasu source and SDK
release. It packages the current auditable Shadow MMP implementation and its
synthetic evidence. It is not a production-readiness claim and does not claim
equivalence with, or replacement of, an existing MMP.

The product and SDK release number is independent of the active Contract v0.4
wire and package identity.

## Changes since v0.2.0-rc.4

- Added authenticated, provider-neutral server event ingestion with dedicated
  app keys, raw-body HMAC, replay controls, durable evaluation, contract
  rejection, idempotency, and deletion-race enforcement.
- Added default-off operator webhooks and deterministic S3-compatible bulk
  exports with destination allowlists, durable retries, privacy notices,
  destination-scoped cursors, and synthetic SigV4 coverage.
- Added durable daily metric schedules and strengthened report, CSV, dashboard,
  and difference-audit pagination around fixed selection boundaries.
- Moved privacy deletion to a durable purge path and added privacy fences to
  SDK projection, Google conversion, AdServices, integrity, Google Play, and
  commerce read-back completion.
- Added bounded worker tenant concurrency and bounded SDK/MAX inbox slices so
  independent tenants can make progress without changing the established
  within-tenant job order.
- Strengthened claim ownership and stale-completion rejection for provider
  queues. Provider-side exactly-once delivery is still not claimed.
- Completed reproducible local Android, iOS source, and Unity UPM packaging,
  including internal SDK-version derivation, least-privilege workflow tokens,
  and a synthetic Unity 6 Android export/APK probe.

## Contract status

- The Contract wire and package identity remains `0.4.0`.
- The additive v0.4 patch ledger remains through v0.4.10.
- The reviewed inventory remains 28 schemas, 8 registries, 57 synthetic
  fixtures, and 741 golden artifacts.
- No schema, registry, fixture, golden, or evaluator behavior changes are part
  of this release closeout.

## Public evidence

- Deterministic TypeScript and independent Python evaluators, PostgreSQL
  parity, RFC 8785 canonicalization, and reviewed golden checks pass.
- The disposable synthetic pilot covers isolated Compose startup, seed,
  persistence parity, API/dashboard/redirector/SDK smoke checks, and cleanup.
- Android JVM/emulator, iOS Swift/Simulator, Contract, and Runtime workflows
  are required to be green at the exact annotated-tag target.
- The local SDK bundle is rebuilt twice and compared byte for byte. Its manifest
  records the same source revision and SDK version that the verification gate
  reads from the release source.

See the [v0.2.0 synthetic evidence manifest](../validation/v0.2.0-synthetic-evidence.md)
for the complete public gate and evidence boundary.

## Residual boundaries

- No real data, provider credential, campaign, device identifier, physical
  device, store track, live domain, production deployment, or operator
  acceptance was used.
- The synthetic Unity 6 Android export/APK probe is implemented. Real Unity
  2022.3 consumer-project export, physical-device execution, and iOS Unity
  export remain unverified.
- Live provider permissions, quota behavior, provider-side duplicate handling,
  notification latency, object-storage operation, and diagnostic delivery
  remain unverified.
- Registry publication, artifact signing, production TLS and secret custody,
  real backup recovery, representative capacity, alert ownership, incident
  response, and formal trademark clearance remain operator or release-owner
  work.
- Fraud calibration, false-positive rates, live integrity projects, device-farm
  coverage, and cross-advertiser intelligence are not established by the
  synthetic rules.
- iOS deferred deep linking is not offered. Direct `deep_link_open` events are
  device-reported and forgeable evidence.
- Verified commerce does not establish entitlement, tax, payout, or complete
  missed-renewal reconstruction.

These boundaries are part of the release. `v0.2.0` is published only if the
annotated tag and GitHub Release point to the same green `main` commit.
