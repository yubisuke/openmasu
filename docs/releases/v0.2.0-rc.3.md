# OpenMasu v0.2.0-rc.3

`v0.2.0-rc.3` is an early release candidate built from public source and
synthetic automated evidence. It is not a production-readiness claim and does
not claim equivalence with, or replacement of, an existing MMP. The product
release number remains independent of the active Contract v0.4 identity.

## Changes since v0.2.0-rc.2

- Added a durable internal scheduler, explicit worker database-pool budgets,
  held-lease completion updates, and transaction boundaries that avoid nested
  connection ownership under bounded pools.
- Added bounded native SDK queues, restart-persistent consent barriers, and one
  shared set of synthetic Android/iOS duplicate and conflict semantics. Unity's
  vendored iOS source is checked against the same behavior.
- Added provider-neutral, no-write import previews and compatibility reports
  for event, cost, and aggregate-revenue mappings. These reports describe only
  the supplied synthetic artifact and do not score or name a provider.
- Rebuilt newcomer documentation around current source-of-truth pages, explicit
  synthetic onboarding, operational boundaries, and release-state separation.
- Upgraded pinned GitHub Actions to Node 24 runtimes and added fail-open pull
  request scope selection. Required job contexts remain visible, superseded PR
  runs are canceled, and `main` pushes and manual runs always execute all gates.

No schema ID, registry entry, reviewed fixture output, golden artifact,
Contract package version, attribution rule, or metric definition changes as
part of the RC.3 release-identity update. Contract v0.4.0 remains the wire and
package identity.

## Contract status

- The active wire identity remains Contract v0.4.0; existing v0.4 schema IDs,
  package versions, and artifact `contract_version` values do not change.
- Deterministic TypeScript/Python evaluation, PostgreSQL parity, RFC 8785
  canonicalization, and reviewed synthetic golden checks remain required.

## Residual boundaries

- No production deployment, live provider authorization, real credential,
  provider acceptance, quota behavior, notification delivery, or diagnostics
  latency has been demonstrated.
- No real data, device, campaign, store track, Unity export, App Store review,
  reinstall, or consumer-project validation was used for this release.
- Registry publication, artifact signing, production TLS and secret
  management, real backups, representative capacity, alert ownership,
  incident response, and formal trademark clearance remain operator work.
- Fraud calibration, live integrity projects, false-positive rates, real device
  farms, reset fraud, and cross-advertiser intelligence remain outside the
  synthetic evidence.
- iOS deferred deep linking is not offered. Direct `deep_link_open` events are
  device-reported and forgeable evidence.
- An SDK installation credential proves control of that installation only.
  Verified commerce does not establish entitlement, tax, payout, complete
  missed-renewal reconstruction, or Apple installation-level revenue binding.

The boundaries above are authoritative for this tag. For later development,
see the [current project status](../STATUS.md); it must not be read as part of
this historical release.
