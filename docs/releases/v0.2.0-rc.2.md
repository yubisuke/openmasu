# OpenMasu v0.2.0-rc.2

`v0.2.0-rc.2` is an early release candidate built from public source and
synthetic automated evidence. It is not a production-readiness claim. The
product release number is independent of the active Contract v0.4 identity.

## Changes since v0.2.0-rc.1

- Added a clean-tree host preflight that verifies the pinned Node.js, npm, and
  Python toolchains, the full contract gate, unit tests, and the source-only iOS
  check while recording every runtime, provider, device, real-data,
  production, and operator gate that was not run.
- Added an isolated disposable Compose pilot in the pinned Runtime workflow.
  It stages tracked source away from host state, strips provider and credential
  environment inputs, uses a unique project and loopback ports, validates an
  empty ledger, seeds reviewed synthetic fixtures, reproduces PostgreSQL/JCS
  parity, runs the API/dashboard/redirector/SDK smoke, records the informational
  synthetic load gate, and verifies resource cleanup.
- Added mechanical documentation-drift checks for validation inventory and
  release identity, and aligned the public release runbook with the automated
  evidence path.
- Changed the default Compose host binding for the API and redirector to
  loopback. This is safer for local evaluation, but an operator who previously
  relied on LAN or remote-host access must configure an explicit host binding.

No contract schema, registry, fixture, reviewed golden, attribution rule, or
metric definition is changed by this release identity update. The loopback
binding change above is the only operational compatibility change since RC1.

## Contract status

- The active wire identity remains Contract v0.4.0; existing v0.4 schema IDs,
  package versions, and artifact `contract_version` values do not change.
- Additive v0.4.1 through v0.4.9 work remains covered by the independent
  TypeScript/Python evaluator and RFC 8785 parity gates.

## Residual boundaries

- No production deployment, live provider authorization, real credential,
  provider acceptance, quota behavior, notification delivery, or diagnostics
  latency has been demonstrated.
- No real data, device, campaign, store track, Unity export, App Store review,
  reinstall, or consumer-project validation was used for this release.
- Registry publication, artifact signing, production TLS and secret
  management, real backups, representative capacity, alert ownership,
  incident response, and formal trademark clearance remain operator work.
- Fraud calibration, live integrity projects, false-positive rates, real device
  farms, reset fraud, and cross-advertiser intelligence remain outside the
  synthetic evidence.
- iOS deferred deep linking is not offered. Direct `deep_link_open` events are
  device-reported and forgeable evidence.
- An SDK installation credential proves control of that installation only.
  Verified commerce does not establish entitlement, tax, payout, complete
  missed-renewal reconstruction, or Apple installation-level revenue binding.
