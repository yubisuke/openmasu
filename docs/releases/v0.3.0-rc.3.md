# OpenMasu v0.3.0-rc.3

Configured prerelease candidate. Publication requires its annotated tag, full
CI at the exact source commit, and verified downloadable SDK assets. Until then,
rc.2 remains the published prerelease; v0.2.0 remains the stable source release.

OpenMasu is an auditable, self-hostable mobile measurement platform for
reproducible attribution and difference explanation. It starts as a Shadow MMP,
not a claim of equivalence to an existing provider.

## Included since rc.2

- UTC daily recorded activity and verified D7 payer metrics with explicit units,
  refund behavior and undefined values.
- Selected ad-group/ad costs and recorded-detail schedule discovery, without
  allocating child spend to parent or sibling ROAS denominators.
- Scheduled aggregate comparisons using existing workers and fixed cutoffs.
- Explicit engagement windows, recorded inactivity and verified purchase-net
  outcomes; historical acquisition and Apple aggregate series stay separate.
- Optional Unity impression-revenue callbacks through existing native queues.
- App-scoped operator keys, default-off bounded retention expiry and PostgreSQL
  tenant-cycle coordination with stale-worker fencing.
- Same-evidence fraud policy previews and receipt-bound activation. Old missing
  rule inputs block impact claims; synthetic counts are not detection accuracy.
- Correct public cost dimension digests for new imports, preserving historical
  artifact identities rather than rewriting them.

The prior 35-item functional plan is included in source. The contract patch
ledger reaches **v0.4.28**; wire/package identity remains **0.4.0** and schema
URNs remain **:v0.4**. This release does not alter reviewed golden artifacts.

## Consumption and compatibility

Use matching source and SDK assets. SDK runtime constants, packages, samples,
SBOMs and the generated HTTP documentation identify 0.3.0-rc.3. No public Maven,
Unity registry or binary Swift distribution is introduced.

Public replacement of an active fraud policy now requires a fresh preview
receipt; clients using the older direct activation form must follow
[the preview workflow](../fraud-preview.md). Missing retained evidence may block
activation. Contract compatibility does not imply every operator API is unchanged.

The existing frozen upgrade gates cover v0.2.0 and v0.3.0-rc.1 only.
**An upgrade from rc.2 is not yet qualified or accepted by the upgrade preflight.**
The concrete follow-up is [#315](https://github.com/yubisuke/openmasu/issues/315).
Use a new disposable synthetic instance for this candidate; do not bypass the
preflight or reset a ledger that must be preserved.

Timezone data remains pinned at tzdata 2025.2; dependency PR #290 is deferred
to a separate calendar-boundary qualification rather than mixed into this release.

## Evidence and limits

See the [synthetic evidence manifest](../validation/v0.3.0-rc.3-synthetic-evidence.md).
Passing source tests is not publication. Publication and downloaded-asset checks
must be recorded separately against their exact source and asset digests.

Real providers, physical devices, store approval, public domains, production
capacity, live alert delivery and private backup custody remain unverified.
Synthetic provider shims do not establish real provider execution. This candidate
is not described as production-ready or a proven replacement for another MMP.
