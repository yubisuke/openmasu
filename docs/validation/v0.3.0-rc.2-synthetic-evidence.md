# v0.3.0-rc.2 Synthetic Evidence Manifest

This is the configured candidate's integration map and evidence requirement,
not a publication receipt. Results must name the exact source SHA and workflow
run. An untagged bundle is not a public SDK release; rc.1 evidence stays frozen.

## First-use path and existing test owners

Use [Getting started](../getting-started.md), not this table, as the operator
walkthrough. Start with a fresh synthetic app, use its registered SDK/backend
credentials locally, select the recommended daily setup, then inspect saved
results and comparison. No provider credentials or manually authored metric
definition JSON are required by the recommended dashboard path.

| Boundary | Existing evidence owner | What is not established |
| --- | --- | --- |
| Clean startup, writer-safe seed, restart, PostgreSQL parity and HTTP | Runtime `pilot:synthetic -- --disposable` | The seed is reviewed reference projection, not an SDK sending every fixture |
| Authenticated receipt and durable processing | `server-events.integration.test.ts`, `m2a.integration.test.ts` | API acceptance is not yet a metric; synthetic HTTP is not device delivery |
| Empty app, authenticated SDK sessions, guided preview/confirm, two campaigns, daily values, saved analysis and exact CSV | `metric-schedule.integration.test.ts` recommended SSR journey | Acquisition/cost setup is fixture-projected; only the retention sessions cross the SDK HTTP/inbox path in this test |
| Late revenue/refund and immutable successor calculations | `late-metric-recalculation.integration.test.ts` | No unbounded history scan or implied complete provider feed |
| Privacy correction, unavailable pending values and actual saved-definition replay | `privacy-metric-recalculation.integration.test.ts` | External recipients have their own deletion obligations |
| Reader snapshot, external declaration, HTML/JSON comparison | `fixed-comparison.integration.test.ts` and offline `demo:shadow` | Operator declarations are not captured external execution |
| Frozen stable and rc.1 backup migration, interruption/resume and privacy reapplication | Parameterized `privacy-reapply.backup.test.ts` in Runtime's dedicated backup step | No live recovery-time or backup-custody claim |
| SDK bundle identity, reproducibility and packaged consumer | Android workflow's packager, standalone UPM Gradle/C# and emulator gates; iOS Swift/Simulator/C# gates | No real-store, physical-device, Unity 2022.3 or actual Unity iOS export acceptance |

The connected journey extends an existing integration test. Correction, privacy,
package consumption and restore keep their current owners; do not copy their
safety matrices into a new end-to-end suite or rerun focused aliases after full CI.

## Identity and upgrade boundary

- Source/SDK candidate: `v0.3.0-rc.2`.
- Contract patch ledger: `v0.4.24`; wire/packages `0.4.0`, URNs `:v0.4`.
- Contract inventory is unchanged: 28 schemas, 8 registries, 71 reviewed
  fixtures and 923 golden artifacts. No golden is regenerated for this release.
- Supported frozen upgrade inputs are `v0.2.0` and `v0.3.0-rc.1`; exact commits,
  counts and inventory digests are in [Safe upgrade](../operations/upgrade.md).
- Upgrade/deployment CLI requires the clean target annotated tag. An untagged
  configured candidate intentionally refuses operator deployment preflight.

## Required candidate receipt

Record the following in the candidate PR/CI receipt before promotion:

1. Accepted head, merged main SHA, unchanged contract/golden diff, and the exact
   `npm run validate` summary.
2. Contract Windows/Linux, Runtime, Android JVM/emulator and iOS results, including
   actual executed steps. PR and main pushes can be path-scoped. Use manual
   dispatch only for missing full gates at the exact selected main SHA.
3. Authenticated receipt-to-calculation assertion, late/privacy successor tests,
   both frozen-source restore cases and zero-failure counts from their owners.
4. Full Android workflow artifact `openmasu-sdk-release-bundle`, its manifest
   `source_revision` and `version`, two-pass equality and checksum verification.
   Do not use a PR merge-preview artifact for release.
5. Remaining unverified provider/device/production gates, never marked passed.

Only after release-owner approval: create the matching annotated tag, verify the
bundle with `--verify-tag`, produce the eight public assets from those same bytes,
publish and re-download them. Record their hashes and source/CI links in a new
publication receipt. Until then the Issue's public-distribution acceptance is
pending, even when source integration and CI are green.
