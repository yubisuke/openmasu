# v0.2.0-rc.4 Synthetic Evidence Manifest

This manifest defines the public, synthetic-only evidence required for the
`v0.2.0-rc.4` release candidate. The annotated tag and GitHub prerelease must
point to the same `main` commit, and every required workflow must be green for
that exact commit. Pull-request path reduction is not accepted as tag-target
evidence. This document does not claim production, provider, device, or
operator validation.

## Host and contract gates

- `npm run pilot:preflight` on a clean tree verifies Node.js 22.18.0, npm
  11.6.2, Python 3.13.5, the complete contract gate, unit tests, and the
  source-only iOS check.
- `npm run validate` must end with:

  `Validated 28 schemas, 8 registries, 57 reviewed fixtures, 741 golden output artifacts, 57 scenario assertions, 27 acceptance criteria, deterministic TypeScript, independent Python, and RFC 8785 conformance.`

- Contract v0.4 package versions and wire identity remain `0.4.0`. The additive
  patch ledger through v0.4.10, 57 reviewed fixtures, and 741 golden artifacts
  are the candidate inventory.

## Disposable Runtime gate

The pinned Runtime workflow runs
`npm run pilot:synthetic -- --disposable --load`. Its bounded JSON evidence must
report a passed status for Compose configuration and startup, empty-ledger demo,
reviewed fixture seed, PostgreSQL/JCS parity, runtime restart and smoke checks,
informational synthetic load, cleanup, and cleanup verification. Every boundary
for real data, external providers, physical devices, production, and operator
acceptance must remain `false`.

The smoke gate verifies that the API emits a tracking URL with the configured
public redirector origin, while route behavior is probed through the isolated
internal Compose service. Worker evidence includes scheduler recovery, bounded
database-pool ownership, import transaction atomicity, and synthetic import
throughput. The pilot uses a run-unique Compose project and removes its
containers, network, volumes, generated secrets, and staging directory.

## SDK release gate

- Android acceptance and five release AAR builds pass.
- Shared queue semantic vectors pass in Android and iOS native tests.
- AdAttributionKit install and re-engagement conversion targets and optional
  conversion tags pass Swift package, Simulator, Unity bridge, and source-copy
  parity checks.
- Android, iOS, and Unity CycloneDX SDK SBOMs are generated.
- `python tools/build-sdk-release.py --reproducibility-check` produces two
  byte-identical trees for `openmasu-sdk-0.2.0-rc.4`.
- `npm run check:sdk-release` verifies exact contents, Maven POM versions,
  archive structure, SBOM format, and complete `SHA256SUMS` coverage.
- Contract, Runtime, Android JVM, Android emulator, and iOS SDK workflows are
  green at the exact tag target. The release uses full `main` push results, not
  pull-request no-op results.

## Verification lookup

The immutable source SHA is the target of the annotated `v0.2.0-rc.4` tag. The
GitHub release page and Actions checks for that SHA are the authoritative run
and artifact references. The release bundle manifest records the same source
revision and SDK version.

## Explicitly unverified

No real export, credential, provider authorization, campaign value, device
identifier, physical device, store track, Unity export, App Store review,
developer-copy delivery, production deployment, external secret manager, real
backup, representative capacity, registry publication, or distribution
signature is used or validated. The synthetic load record is informational and
is not a production service level objective.
